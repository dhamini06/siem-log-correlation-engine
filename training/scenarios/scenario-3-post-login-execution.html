Scenario 03 Medium Rule: suspicious_process_post_login Expected severity: high

Suspicious Post-Login Process Execution

A Windows account authenticated, then launched a command shell seconds later. Measure the gap, read the command line, and explain why it matters.

Incident Brief

What you are working

Security objective

Establish that a user authenticated and then executed a suspicious process on the same host within the detection window, and determine from the command line what the actor was attempting.

Incident story

Endpoint telemetry on a Windows application server shows an account signing in and then immediately spawning a shell. There is a high-severity alert on the SOC Triage Board for this. Unlike Scenarios 01 and 02 there are no preceding failed logons here — the authentication itself succeeded legitimately, and the risk is in what happened after it.

What you know at the start

  • Windows process creation is logged as process_create with a process object.
  • The host in question is a Windows application server, not the Linux web server.
  • The alert you need is on a different host from Scenarios 01 and 02.
Investigation task

Your mission

  1. Locate the alertIt is a suspicious_process_post_login alert on a Windows host.
  2. Measure the timingFind the logon and the process creation. What is the exact gap, and how does it compare to the rule's window?
  3. Read the command lineThe full argument string is the most important evidence in this scenario. Explain what each part is trying to achieve, and read parent_name to see how the shell was launched.
  4. State the findingWhat does this sequence indicate about the account's intent?

    What a complete finding covers
    • evidence: who, where, from where and when
    • evidence: the command activity, in order
    • assessment: why it is suspicious
    • impact: what an attacker now holds
    • response: immediate containment

    Cover all four. EVIDENCE: the account, the host, the source address, the interval after authenticating, the process, and both operations in its command line in the order they ran. ASSESSMENT: what those operations are for, and what the parent process tells you about who was driving. IMPACT: what an attacker now holds on that host. RECOMMENDED RESPONSE: the immediate steps and why they are urgent. Naming the process without assessing it does not satisfy the rubric.

Progressive Hints

Hint 1 — finding the right alert

The SOC Triage Board contains two alerts from the suspicious_process_post_login rule. Scenario 04 is the other one. This scenario is the Windows host — look at the "Alerts by Host" panel, or filter the alerts by host for a Windows-looking name such as app-01 rather than web-01.

Hint 2 — the timing evidence

The alert's first_seen is the logon and last_seen is the process creation — the SIEM already recorded the delta for you. Subtract them to get the gap in seconds. The rule parameter is time_after_login_minutes in config/app-config.yaml.

Hint 3 — reading the command line

Expand the process object on the evidence event and read command_line in full. Shell chains are usually separated by &&. Read the raw Windows event as well: the raw_event field contains the original 4688 record.

Hint 4 — interpreting the commands

Consider each part separately. One command identifies the current account and its privilege level. The other modifies the local administrator account — consider what enabling or re-enabling a built-in administrator account is used for after an attacker already has a foothold.

Hint 5 — the parent process

process.parent_name and parent_pid are on the same event. Think about which Windows component launches a shell directly at logon, and contrast it with the shells that appear in the benign process_create events on the same host.

Hint 6 — is it related to the brute force?

Compare the hosts, the users and the source IPs. Then compare the timing. If they do not share an identity or a source, they are separate activity and you should report them as such — do not merge unrelated alerts into a single story.
