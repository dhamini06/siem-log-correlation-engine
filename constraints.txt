# Transitive dependency pins for a reproducible install.
#
#   python -m pip install -r requirements.txt -c constraints.txt
#
# Why this file exists
# --------------------
# requirements.txt pins the six packages this project imports directly. It does
# not pin what those packages pull in, and pip is otherwise free to resolve
# each of those to whatever is newest on the day of the install. Two technicians
# installing this lab a fortnight apart could therefore end up with different
# code, and a server that fails to install is a server nobody can reproduce the
# build of.
#
# Scope and limits
# ----------------
#   * These pins MUST stay consistent with the direct pins in requirements.txt.
#     A constraints file cannot override a direct requirement: if the two
#     disagree, pip reports a conflict rather than resolving it. Test F in
#     tests/test_deployment_hardening.py asserts that consistency mechanically,
#     so the two files cannot drift apart unnoticed.
#   * Every version below is a py3-none-any wheel: no compilation on the
#     target, and no compiler on a host where sudo is restricted.
#   * This is NOT an upgrade. Nothing here moves a package above the version
#     requirements.txt already asks for.
#   * This does NOT pin the whole world. Transitive-of-transitive packages
#     (pytest's own pluggy/iniconfig chain, for example) are deliberately left
#     floating: they are test-only, they cannot affect the running lab, and
#     pinning them adds maintenance for no deployment benefit.
#
# Verified: every version here exists on PyPI and ships a universal wheel.
# The server target is CPython 3.14 on Ubuntu.
